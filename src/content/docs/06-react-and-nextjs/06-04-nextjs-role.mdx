Next.js는 React 위에서 동작하는 풀스택 프레임워크다. 라우팅, 렌더링 전략, 번들링, 이미지 최적화 등을 기본 제공한다. App Router(Next.js 13+)가 현재 표준이다.

## 파일 기반 라우팅

App Router는 `app/` 디렉터리 구조가 곧 URL 구조다.

```text
app/
├── layout.tsx          → 모든 페이지 공통 레이아웃
├── page.tsx            → / (루트)
├── about/
│   └── page.tsx        → /about
├── blog/
│   ├── page.tsx        → /blog
│   └── [slug]/
│       └── page.tsx    → /blog/my-post (동적 세그먼트)
└── api/
    └── users/
        └── route.ts    → /api/users (API Route)
```

동적 세그먼트는 대괄호로 표현하며, 컴포넌트에서 params로 접근한다.

```tsx
// app/blog/[slug]/page.tsx
interface Props {
  params: Promise<{ slug: string }>
}

export default async function BlogPost({ params }: Props) {
  const { slug } = await params
  const post = await fetchPost(slug)

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  )
}
```

## SSR / SSG / ISR

2026-10-23 공식 문서는 Next.js 16.4.3의 Cache Components 모델과 기존 모델을 구분한다. 새 `create-next-app` 권장 기본값에는 Cache Components와 Partial Prefetching이 켜진다. 기존 앱은 `next.config.ts`를 확인해야 한다. `async` 함수라는 이유만으로 요청마다 SSR이 되지는 않는다.

아래 세 예제는 `cacheComponents: false`인 기존 모델을 설명한다. `fetch`의 데이터 캐시와 페이지 HTML의 사전 렌더링은 다른 층이다. 기본값 대신 예제의 의도를 명시한다.

### SSR (Server-Side Rendering)

요청이 올 때마다 서버에서 렌더링한다.

```tsx
// 기존 캐시 모델: cacheComponents: false
export default async function Dashboard() {
  // 요청마다 최신 데이터 조회
  const data = await fetch('https://api.example.com/stats', {
    cache: 'no-store'  // 캐시 비활성화 = SSR
  })
  const stats = await data.json()

  return <div>활성 사용자: {stats.activeUsers}</div>
}
```

### SSG (Static Site Generation)

빌드 타임에 HTML을 생성한다. 배포 후 콘텐츠가 변하지 않는다.

```tsx
export default async function AboutPage() {
  // 기존 캐시 모델에서 데이터 캐시 사용을 명시
  const content = await fetch('https://api.example.com/about', { cache: 'force-cache' }).then(r => r.json())

  return <div>{content.text}</div>
}

// 동적 경로의 SSG: 어떤 slug를 미리 빌드할지 알려줌
export async function generateStaticParams() {
  const posts = await fetchAllPosts()
  return posts.map(post => ({ slug: post.slug }))
}
```

### ISR (Incremental Static Regeneration)

SSG의 확장판. 주기적으로 백그라운드에서 페이지를 재생성한다.

```tsx
export default async function PricingPage() {
  const prices = await fetch('https://api.example.com/prices', {
    next: { revalidate: 3600 }  // 1시간마다 재검증
  })
  const data = await prices.json()

  return <div>{/* 가격 정보 */}</div>
}
```

### Cache Components 모델

다음은 위 기존 모델과 별도 예제다. `use cache`로 캐시할 함수·컴포넌트를 명시하고, 요청 시점의 데이터는 `Suspense` 경계 안에서 가져온다.

```typescript
// next.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}
export default nextConfig
```

```tsx
// app/page.tsx
import { Suspense } from 'react'
import { cacheLife } from 'next/cache'
import { connection } from 'next/server'

async function Catalog() {
  'use cache'
  cacheLife('hours')
  const response = await fetch('https://api.example.com/catalog')
  if (!response.ok) throw new Error('카탈로그 요청 실패')
  const items = await response.json()
  return <p>공개 항목 {items.length}개</p>
}

async function RequestTime() {
  await connection()
  return <p>요청 시각: {new Date().toISOString()}</p>
}

export default function Page() {
  return <>
    <Catalog />
    <Suspense fallback={<p>요청 정보 로딩 중...</p>}>
      <RequestTime />
    </Suspense>
  </>
}
```

Cache Components를 켠 경우 기존의 route segment `dynamic`·`revalidate`·`fetchCache` 설정을 그대로 혼합하지 않는다. `cacheLife`, `cacheTag`, 재검증 API는 해당 모델의 공식 문서를 따른다. ISR의 시간 값은 정확히 매시 정각에 실행하는 스케줄러가 아니다.

### 렌더링 전략 선택 기준

| 전략 | 데이터 특성 | 예시 |
|------|------------|------|
| SSG | 빌드 후 변경 없음 | 회사 소개, 법적 고지 |
| ISR | 주기적 업데이트 | 블로그, 상품 목록 |
| SSR | 요청마다 달라짐 | 대시보드, 개인화 피드 |
| CSR | 인터랙션이 핵심 | 에디터, 실시간 협업 |

## React Server Components

App Router의 핵심 개념이다. 컴포넌트를 서버에서만 실행되는 것과 클라이언트에서 실행되는 것으로 분리한다.

```tsx
// Server Component (기본값) — 'use client' 없음
// 서버에서만 실행되므로 DB, API Key, 파일 시스템 직접 접근 가능
import { db } from '@/lib/db'

export default async function PostList() {
  const posts = await db.query('SELECT * FROM posts')  // 서버에서만 실행

  return (
    <ul>
      {posts.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  )
}
```

```tsx
// Client Component — 'use client' 선언 필수
'use client'

import { useState } from 'react'

export default function LikeButton({ postId }: { postId: number }) {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? '❤️' : '🤍'}
    </button>
  )
}
```

### Server vs Client Component 비교

| 기능 | Server Component | Client Component |
|------|-----------------|-----------------|
| useState / useEffect | 불가 | 가능 |
| DB 직접 접근 | 가능 | 불가 |
| API Key | 서버에 보관. props·응답에 넣으면 노출 | 브라우저 번들·응답에 비밀을 넣지 않음 |
| 브라우저 JS | 컴포넌트 구현 코드는 제외, 렌더 결과는 전달 | 코드가 브라우저 번들에 포함 |
| 브라우저 API | 불가 | 가능 |

`use client`는 모듈의 클라이언트 경계를 선언한다. Client Component도 최초 요청에서 서버가 HTML을 사전 렌더링할 수 있으므로, 렌더 중에 `window`를 무조건 읽지 않는다. Server Component를 Client 모듈에서 직접 import하지 않고, 서버 부모가 만든 요소를 `children` 같은 prop으로 전달해 조합할 수 있다. 서버 비밀을 props나 직렬화 결과로 전달하면 Server Component에서도 유출된다.

## Route Handlers

App Router의 `route.ts`는 Route Handler다. 같은 프로젝트에서 HTTP 엔드포인트를 처리하지만, 동적인 요청 처리에는 서버 런타임이 필요하다. 입력 검증·인증·인가를 별도로 구현한다.

```typescript
// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const users = await fetchUsersFromDB()
  return NextResponse.json(users)
}

export async function POST(request: NextRequest) {
  const body = await request.json()
  const user = await createUser(body)
  return NextResponse.json(user, { status: 201 })
}
```

AI 엔지니어 관점에서 API Routes의 주요 용도:

```text
- FastAPI 호출을 프록시 (CORS 처리, API Key 숨김)
- 간단한 웹훅 처리
- 폼 제출 처리
- LLM 스트리밍 응답을 클라이언트로 중계
```

복잡한 비즈니스 로직과 ML 처리는 FastAPI에, UI 관련 API는 Next.js API Routes에 두는 것이 일반적이다.

## 핵심 정리

- **App Router는 파일 경로가 URL이다** — `app/blog/[slug]/page.tsx` → `/blog/my-post`
- **캐시 모델을 먼저 확인한다** — 기존 fetch 캐시와 Cache Components의 `use cache`·`Suspense` 모델을 구분한다
- **Server Components는 서버에서만 실행된다** — 구현 코드는 브라우저 번들에서 제외되고, DB 직접 접근이 가능하다. props·출력으로 비밀이 노출되지 않도록 한다
- **Client Components는 `'use client'` 를 선언한다** — 인터랙션, 브라우저 API, Hook 사용 가능
- **Route Handlers는 App Router의 HTTP 엔드포인트다** — FastAPI 프록시나 간단한 처리에 활용한다
